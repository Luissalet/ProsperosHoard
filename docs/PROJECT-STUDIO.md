# Project dashboard and clip studio

Selecting a project always opens **Project**. Its dashboard shows project videos with a direct **Edit video** action, recent assets and cast. **+ Character** and **+ Group** open inline editors; existing entries edit in the same place. The full cast manager remains available for the other cast operations.

**Create clip** opens video creation directly. Choose or upload a start image, write its motion and generate in the video node. Reference nodes connect automatically; drag their headings to arrange the canvas, pan or use zoom/fit controls. Optional motion-video and end-frame nodes accept uploads and library choices. Use one optional guide per generation. Camera, duration, engine and seed remain available, as do take selection, comparison, enlargement and download.

The video node shows queued, waiting for GPU, running, failed, cancelled and completed states. Reloading recovers the last job before enabling another generation. A failed status lookup offers retry and does not imply that the generation stopped. A completed job loads its own output; a deliberately selected previous take remains selected when returning to the studio. The preview identifies that take while another job runs.

Click an image shot's own storyboard card to open its connected frame/video workspace directly. This works without a frame and keeps the production slug and shot key. Save keeps the workspace open; Save and render uses the existing production pipeline, which may also complete other pending shots. The workspace stays open when the job reaches a review pause or finishes and displays the clip from that shot's production state. Its frame selection follows asset identity when a generation replaces the variants. Approval, timing, cast, takes and chaining remain in Shot settings; Back to storyboard restores the production navigation. Graphic shots and inserting a new shot retain their existing editors.

The shot's primary status follows its actual frame and clip: missing both, frame ready with clip pending, clip generated, or a still-image shot with no clip required. Production progress, review pauses and failed-job details appear separately; a finished production job never makes an empty shot complete. The always-present **References** node connects to the frame. Add from the library or upload a file, extract a video frame or import a link, describe its use, replace or remove it, then Save. Up to six references use the same native shot payload; the standalone image-shot editor retains its reference controls in settings.

The standalone **Create clip** studio still creates project assets separately. It does not replace a production shot automatically. The storyboard's node workspace uses the native production rendering and take-selection workflow instead.

Video production keeps **Storyboard**, **View** and **Text and takes** as primary sections. The process outline, quality and history remain reachable through their labelled disclosures. On mobile, clip references and video controls stack vertically rather than shrinking the graph.

Verification used an isolated synthetic demo, native stdio MCP and hidden browser captures at 390, 1440 and 1883 pixels, including light/dark themes. The 1090 correction passed 1114 Python tests (4 skipped, 3 warnings), frontend build and 23 Node tests; its reference/status captures cover 390, 1116 and 1440 pixels. This verifies interaction and job transport, not image/video model quality. `scripts/screenshots.py` was replaced by equivalent browser-tool captures because direct Playwright browser control is unavailable in this environment.
