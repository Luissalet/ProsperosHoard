# Prospero929: retry failed native shutdown

Independent review of CAS4 reproduced a real lifecycle defect: a second __aexit__ on an exhausted lifespan could discard its app and announce OFF after cleanup failed. This change records the first exit attempt, retains the app/stopping state on error, retries the factory's explicit async retry_shutdown thereafter, and rejects ON until shutdown really succeeds. Factories without a retry callback remain owned with a clear error. No SDK changes.

Generation's existing synchronous shutdown API is retained; its resource steps are recorded only after each succeeds. Editing exposes its real Services.stop through the retry callback and likewise retains completed steps. Link closure failures now propagate instead of silently declaring success. The common UI shows Cierre pendiente/Reintentar apagado; a failed module-control PUT returns JSON503 with the native error and retained module state, avoiding the former JSON parse error on a plain500 response.

CUA of the installed package also found the editing header's old /icon-192.png and old product title. Its existing Logo now uses Prospero's own icon and the editor title identifies Prospero · Montaje. The native UI was rebuilt from source; native formats/tool APIs/IDs remain unchanged.
